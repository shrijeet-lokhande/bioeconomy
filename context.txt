5. AUTHENTICATION (implemented + verified, Task 002)
======================================================================
Backend endpoints (/api/v1/auth):
- POST /register — 201 UserPublic; 409 dup (case-insensitive, race
  safe); 422 validation; ignores client role/is_active fields.
- POST /login — 200 UserPublic + HttpOnly SameSite=Lax cookie
  bio_session; generic non-revealing 401; dummy-hash timing
  equivalence for unknown email; 403 inactive accounts.
- POST /logout — 204, revokes session + clears cookie (replay-safe).
- GET /me — 200 UserPublic / 401 unauthenticated|expired|revoked.
Design:
- Argon2id hashes (argon2-cffi OWASP defaults); only token SHA-256 in
  auth_sessions; absolute 7-day expiry; purge on login.
- CSRF: SameSite=Lax + Origin allow-list on unsafe methods; CORS
  allow-list from settings; COOKIE_SECURE must be 1 in production.
- Rate limiting: process-local scope-keyed enforce_rate_limit
  (register/login, 5/min per IP) — documented limitation; Redis
  shared limiter = follow-up.
- Password reset: NOT implemented. Not claimed anywhere.

Data model (migration 8a2056eb9760, autogenerate; chain has exactly
one revision today):
- users: id UUID pk, full_name(200), email(320) UNIQUE lowercase,
  password_hash(255), role(32) default 'user', is_active, created_at/
  updated_at (tz-aware).
- auth_sessions: id UUID pk, token_hash(64) UNIQUE, user_id FK
  CASCADE, expires_at, revoked_at, created_at.

Key reusable internals for Task 003:
- sessions.py: generate_session_token()/hash_token() = security
  pattern to mirror for verification tokens.
- rate_limit.enforce_rate_limit(request, scope) — add scopes.
- api/auth.py: _untrusted_origin(request), _set_session_cookie(...),
  get_current_user in api/dependencies.py (gate point for verified-
  email enforcement).
- conftest.py: isolates bioeconomy_test_<hex> DB via migration chain;
  admin ops (CREATE/DROP DATABASE) run over a connection to the
  bioeconomy DB in AUTOCOMMIT mode (TCP to `postgres` DB fails pg_hba
  auth for the app role). str(URL) MASKS PASSWORDS — use
  render_as_string(hide_password=False).

7.1 DATABASE (one new Alembic revision on top of 8a2056eb9760)
- users: + is_email_verified bool server_default false;
  + email_verified_at nullable tz-aware timestamp.
- NEW table auth_email_verification_tokens: id UUID pk, user_id FK
  CASCADE, token_hash(64) UNIQUE (SHA-256 of raw token — raw never
  stored), expires_at, consumed_at nullable, created_at. Chosen over
  columns-on-users: per-issue tokens, supersede policy, queryable
  consumed/expired state machine; mirrors auth_sessions pattern.
- Migration behavior: existing users DO NOT auto-verify (stays
  false). Admin verification path = documented explicit process in
  docs/DATABASE.md. OPEN DECISION (user input, default stands):
  documented admin SQL vs small CLI `python -m backend.admin
  verify-email <email>`.

7.2 TOKEN DESIGN
- secrets.token_urlsafe(32) (256-bit); only SHA-256 stored; expiry
  30 min via VERIFICATION_TOKEN_MINUTES (configurable).
- ATOMIC consumption: single conditional UPDATE ... SET consumed_at=now()
  WHERE token_hash=:h AND consumed_at IS NULL AND expires_at>now()
  RETURNING user_id; mark user verified in SAME transaction. Row-level
  atomicity makes concurrent double-use impossible.
- Resend policy: issuing a new token SUPERSEDES all prior unconsumed
  tokens for that user; purge expired/consumed opportunistically.

8.1 AUTHORIZATION MODEL
- Gate order per request: 401 (no/bad/expired/revoked cookie or
  inactive owner) -> 403 {code:"email_verification_required"}
  (session on unverified account) -> 403 {code:"admin_required"}
  (verify user role != 'admin'). codes.py adds ADMIN_REQUIRED_*.
- require_admin lives in backend/src/backend/api/admin.py
  (router prefix /api/v1/admin, tag admin). Roles are RE-READ from
  the DB every request: a flipped role applies to an already-issued
  session on its next request (test proves both directions).
- NO endpoint can create an admin anywhere: the only bootstrap is
  operator SQL: UPDATE users SET role='admin' WHERE email='<…>';
  (docs/DATABASE.md). Executed once for shrijeet733@gmail.com (also
  verified 2026-10-24), so the user can sign in and use the panel.
- Self-protection (server-side 400s): admin cannot deactivate their
  own account, un-verify their own account, or demote their own role
  (last-admin lockout guard). Other admins are fair game.

8.2 ENDPOINTS (all under /api/v1/admin)
- GET /overview -> {total_users, verified_users, active_users,
  admin_users, live_sessions, recent_registrations[5]}.
- GET /users?search&page&page_size -> {total, page, page_size,
  items:[AdminUserSummary]}; search = ILIKE over email/full_name,
  ordering always created_at DESC, page 1-…, page_size 1-100.
- GET /users/{id} -> AdminUserDetail incl. latest 50 session ROWS as
  metadata only (id, created, expires, revoked, live) — token
  hashes are NEVER exposed (test asserts absence).
- PATCH /users/{id} {is_active?, is_email_verified?} -> updated
  summary; un-verify/deactivate ALSO revokes all live sessions of
  the target in the same action (DB-verified); un-verify clears
  email_verified_at, force-verify stamps it; no-op = 200.
- POST /users/{id}/sessions/revoke {} (all) | {"session_id":…} (one)
  -> {"revoked": n}; unknown session id on real user = 200 n:0;
  unknown user = 404 generic "User not found.".
- POST /users/{id}/role {"role":"user"|"admin"} -> updated summary;
  other values 422; unknown user 404.
- Mutations run _untrusted_origin 403 + rate limit scope "admin";
  CORS allow_methods is now ["GET","POST","PATCH"] in main.py which
  also includes the admin router.
